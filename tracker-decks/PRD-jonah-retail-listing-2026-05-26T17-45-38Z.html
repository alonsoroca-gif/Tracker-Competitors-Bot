PRD: Retail/Commercial Tenant Listing Module for Mixed-Use Property Sites

Drop: 2026-05-26T17-45-38Z · Tier Now · Effort S · Triggered by Jonah Digital "Retail Page" add-on

Problem

Jonah Digital advertises a "Retail Page" add-on for mixed-use multifamily marketing sites — same property, ground-floor retail tenants displayed alongside residential availability. As mixed-use portfolios grow, the marketing site has to carry both stories: residential leasing and "here's the coffee shop, the restaurant, the gym downstairs". Entrata has commercial-customer infrastructure inside Core but no prospect-facing retail-tenant listing UI on the leasing-website surface. The structural reason this matters: the underlying commercial-customer + lease data is already in Entrata — we just don't expose it on the prospect-marketing pages a website-builder like Jonah is trying to fill. They have to manually maintain a separate "retail page"; we can drive it directly from the source of truth.

Target user

A residential prospect researching a mixed-use property (apartment + retail + restaurant + services downstairs) who wants to know what's at the property before they tour. Secondary: property marketing teams who currently maintain retail-tenant lists manually in CMS systems.

Originating signal classification

Product / capability (manager-confirmed via §4.2a on the 2026-05-26T17-45-38Z cycle).

Scope (in)

  • "Retail at this property" page template in EntrataLeasingWebsite / ProspectPortal. New page type alongside existing residential pages.
  • Read-only API binding from commercial-customer records (existing Core data) to the leasing-website page. Tenant data flows: name, category, business hours, website URL, logo, brief description.
  • Tenant-category filters on the page: restaurant, retail, services, fitness, etc.
  • Optional "now leasing — commercial availability" surface for vacant commercial units (re-uses existing commercial-availability data; surfaces vacancy without a separate workflow).
  • Property-config toggle in admin to enable/disable the retail page per property (mixed-use only).
  • Mobile-responsive, follows existing EntrataLeasingWebsite template patterns.

Scope (out)

  • Commercial leasing application flow — residential prospect flow only. Commercial-lease leads route to the commercial sales team via the existing pipeline.
  • Tenant content management UI for property managers to edit retail-tenant pages directly. v1 reads from existing commercial-customer records; editing happens through the existing commercial-customer UI in Entrata, not a new surface.
  • Retail-tenant reviews / ratings — defer.
  • Cross-property retail discovery (e.g., "all coffee shops at properties in Salt Lake County") — defer.

Success metric

Adoption: # of mixed-use properties on Entrata that enable the retail page within 6 months of launch. Target: 50% of identified mixed-use portfolio (mixed-use = properties with ≥1 commercial-customer record). Secondary: prospect engagement metric — % of sessions on mixed-use property pages that visit the retail page (no target set in v1; baseline-establishing).

The commercial-customer data layer itself is reused unchanged — no new write paths, no schema changes to commercial-customer records.

Net-new engineering ask

  • Read-only API binding from commercial-customer records to leasing-website page — backend, S. Internal API endpoint exposing commercial-tenant data filtered by property_id + is_prospect_facing.
  • Tenant-category filter UI on the new page — frontend, S. Reuses existing filter primitive from residential pages.
  • Property-config toggle to enable/disable the retail page per property — admin, S. New boolean on property_config; default false; only properties with ≥1 commercial-customer record see the toggle.

Effort estimate

S (small). Read-only surface on top of existing commercial-customer data; no new write paths, no schema changes, no integration with new third-party systems. Single team can ship; primary work is frontend template + a read-only backend endpoint.
