PRD: Interactive Siteplan / Map Embed in ProspectPortal

Drop: 2026-05-26T17-45-38Z · Tier Now · Effort M · Triggered by Jonah Digital + Engrain SightMap integration

Problem

Jonah Digital advertises Engrain SightMap on prospect-facing leasing websites, letting a renter see which units in which building are available, on an interactive map of the property, with live pricing. Entrata's ProspectPortal today shows unit lists + floorplans but has no spatial map UI. The structural reason this matters: ProspectPortal sits between PMS pricing/availability and the prospect — Entrata owns that stack end-to-end and can ship a map that's live-bound to PMS in a way a website-builder like Jonah structurally cannot. Jonah has to integrate with a third party (Engrain) and wire pricing through an external API; we have the data in the same database.

Target user

A prospect on a property's leasing website who wants to see where available units are on the property before tour. Especially valuable for larger garden-style and mixed-rise communities where "Building C, 2nd floor, corner" matters to the renter's mental model.

Originating signal classification

Product / capability (manager-confirmed via §4.2a on the 2026-05-26T17-45-38Z cycle).

Scope (in)

  • Property-level interactive site plan UI (SVG or canvas-based) embedded in ProspectPortal as a new view alongside the existing unit list + floorplan views.
  • Unit markers on the map clickable to drill into the existing unit detail page (no new detail page work).
  • Live binding to PMS-driven availability + pricing — reuses the existing ProspectPortal data layer; no new pricing or availability work.
  • Filter integration: bedroom count, floor, price range, move-in date — applied on the map view by reusing ProspectPortal's existing filter state.
  • Mobile-responsive with touch + pinch zoom.
  • Property-admin upload tool for the underlying site-plan SVG with unit overlay positions (one-time setup per property; saves to a new property_siteplan record).

Scope (out)

  • 3D building rendering — defer to a future PRD.
  • Floor-by-floor virtual tour — defer.
  • Outdoor amenity hotspots beyond the unit markers — defer.
  • Real-time multi-user state on the map (e.g., "12 people are looking at this unit") — defer.

Success metric

≥25% of prospect sessions include a click on the map view within 90 days of GA across pilot properties. Secondary: tour-request rate on map-view sessions vs. list-view sessions (target: equal or better, not worse — i.e., the map doesn't cannibalize conversion).

Evidence

tracker-drops/2026-05-26T17-45-38Z/signals.json row matching competitor_id=jonah-digital + source_url=https://jonahdigital.com/add-ons/ (importance 0.84). Same Add-Ons page lists SightMap, Retail Page, and Tour Scheduler — this PRD covers only the SightMap line.

Existing Entrata implementation

ProspectPortal ships unit availability + floorplan UI + PMS pricing data layer. Core parity check (richer-vocab pass) returned 540 score / 87 files / 12 apps spanning floorplan, unit, pricing, and prospect-portal modules — the data + UI surface is there. What does NOT exist: an interactive spatial-map widget tied to that data; the existing UI presents units as a list or grid of floorplan cards, never positioned on the physical property layout. The 2026-05-12 manager review's borderline-sightmap-siteplan regression fixture confirms the spec-level read: Partial parity at the threshold, not Existing.

Delta vs Core

The interactive-map widget itself (SVG site plan renderer, unit-marker overlay, click-to-drill interaction, admin site-plan upload tool). Everything below the widget — pricing engine, availability engine, unit detail page, prospect filter state — is reused unchanged. This is a presentation-layer PRD on top of existing data.

Net-new engineering ask

  • Site-plan SVG renderer with unit-marker overlay — frontend, M. Build the rendering primitive that overlays unit positions on a property SVG; click handlers drill to existing unit detail.
  • Property-admin tool to upload site-plan + position unit markers — backend + admin UI, M. One-time-per-property setup; saves to a new property_siteplan table with unit-marker JSON.
  • Mobile touch + pinch-zoom interactions — frontend, S. Standard mobile gesture handling on the renderer.
  • Filter integration with existing ProspectPortal filter state — frontend, S. Map view subscribes to the same filter state the list view already uses.
  • Analytics events for map-view engagement — instrumentation, S. New events: siteplan_view, siteplan_unit_click, siteplan_filter_change.

Effort estimate

M (medium). Assumes ProspectPortal floorplan + PMS pricing layers are reused without modification. The work splits across two teams: ProspectPortal frontend (renderer + filter integration) and admin tooling (upload tool + position editor). No new pricing-engine or availability-engine work.
